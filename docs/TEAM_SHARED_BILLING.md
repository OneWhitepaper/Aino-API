# 团队共享额度

用户侧入口为“额度使用方式”(`/funding`) 和“团队共享管理”(`/team-sharing`)。
此功能用于标准计费模式；简易模式不会执行共享付款。

## 资金与权限

- 组织人的余额为同一个资金池，不复制、不预分配给成员。个人余额和个人订阅独立保留。
- 邀请面向已存在的用户 ID，需要目标用户接受，有效期 7 天；系统不发送邮件。
- 成员上限是加入该团队以来的累计共享消费上限，覆盖共享余额和共享订阅。`null` 表示不限，`"0"` 表示不允许继续共享；重新加入不会清零历史消费。
- 暂停、移除和退出撤销后续共享授权。已接受并预留的请求按原快照继续处理和结算，历史记录保留。
- 组织人选择共享哪些订阅、余额和订阅的顺序，并可设置成员覆盖。组织人的个人来源建议不会覆盖成员的个人付款授权。
- 共享订阅只授予被选中且有效订阅的对应分组权限，仍受模型、有效期和日／周／月限制约束。
- 单次请求只选择一个付款来源，不拆分账单、不递归使用另一个团队。模型价格与倍率继续使用调用人的分组设置。

## 成员付款方式

个人来源仍受成员授权开关控制；未授权的来源从下列顺序中移除。

| 方式 | 顺序 |
| --- | --- |
| 优先个人余额 | 个人余额 → 个人订阅 → 所选团队 |
| 仅用个人余额 | 个人余额 |
| 优先团队共享额度 | 所选团队 → 个人订阅 → 个人余额 |
| 仅用团队共享额度 | 所选团队 |
| 优先个人订阅 | 个人订阅 → 个人余额 → 所选团队 |
| 仅用个人订阅 | 个人订阅 |

团队内部使用其有效的默认／成员级共享资源顺序。“仅用”耗尽时不会改扣另一类来源。新来源只能在派发前选择，派发后不切换付款人。

未设置偏好的普通用户保持既有扣费行为。创建团队的组织人自动进入资金池并发保护；未保存偏好时仍按原分组的余额或订阅方式付款。

## 当前请求支持范围

共享付款覆盖文本、Embedding、图片、音频转写与语音合成、视频、批量生图及异步任务；包括 Gemini 原生生成、显式缓存、收费搜索工具，以及 HTTP/OAuth、WebSocket 多轮和有明确时长上限的实时语音。

每次请求按实际计费单位和调用人的价格预留额度。图片按张数／尺寸或图片 token、音频按字符／可验证时长、视频按时长／分辨率或输出 token、缓存按存储 token 小时计费。批量生图使用完整费用上界，不使用个人冻结余额或不充分的预留倍率。

共享文本请求未提供输出上限时补充 4096。远程附件、服务端会话及 OAuth 删除客户端输出上限的情况，使用实际账号的模型上下文／输出上限重新核算；模型上限、原生生图最大张数或托管工具调用上限缺失时，在派发前返回具体配置错误。不会根据合成的目录默认值或模型家族名猜测这些上限。单次请求始终使用一个付款来源。

WebSocket 按每轮请求独立授权并保存付款快照。实时语音使用网关强制执行的会话期限，异常断开仍结算已观测用量。既有 OpenAI Live 免费行为保持原样。

异步任务的付款信息和终态用量保存于 PostgreSQL。查询、下载、取消及结算按任务的原始调用人／API Key 验证所有权，不要求成员仍有余额或仍在团队；新请求仍重新校验共享授权。缓存扩展使用原付款来源建立新预留，不复用已结算的创建请求。

桌面端继续使用原账号、设备凭据、模型目录和 `billing_source: balance|subscription` 协议，后台保存调用人与付款人。个人钱包接口不合并团队资产。

## 账务与恢复

- PostgreSQL 预留占用真实余额或订阅窗口，成员上限检查与预留在同一事务中完成。
- 付款快照和预留随请求保存；结算加入已有用量去重事务，同时更新付款人、成员消费和团队账本。
- 共享调用及采用预留的有界个人调用应对一次逻辑操作复用 `Idempotency-Key`，桌面端也可使用既有操作／调用标识。未提供重试标识的两次独立 HTTP 请求不能识别为同一操作；未采用预留的个人调用保持原有去重约定。
- 有预留的操作由数据库保证只有一次上游派发；不会在未知结果后自动重试另一账号或付款来源。
- 未派发请求释放预留；明确且无用量的上游拒绝可释放。网络中断、未知响应或已派发但未结算的请求不按超时自动退款，需运维依据上游用量核对。
- 正常结算退回多余预留。若实际费用意外高于已授权上界，超出部分单独保存供核对，不擅自多扣个人资金或突破成员上限；相关共享资源暂停后续使用。
- 团队账本的 `amount` 为实际扣费，`unauthorized_amount` 为未计入实际扣费的待核对金额。旧请求跨越共享启用时的未支付差额保存在 `funding_billing_shortfalls`。

数据库迁移为 `257_team_shared_billing.sql` 至 `261_gemini_cache_funding_snapshots.sql`。音频转写的时长验证需要运行环境提供 `ffprobe`，项目 Docker 镜像已包含。上线前应备份数据库，并保留预留、账本和去重记录以供核对。
