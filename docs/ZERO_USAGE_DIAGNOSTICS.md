# 零用量响应诊断

API 复用既有 `openai_usage.success_missing_usage` 警告，覆盖 HTTP Chat Completions 直转的流式与非流式响应，以及已接入同一警告的 Responses 协议路径。

触发条件是上游成功状态、已识别的结束信号，以及最终解析用量的所有计费 token 均为零。正常用量、仅缓存用量、已有错误或截断处理不会被改为零用量成功。该记录只提供诊断，不补算 token、不改价格、结算、客户端响应或请求重试行为。

记录字段采用白名单：请求 ID、用户/Key/分组/上游账号 ID、安全模型标识、协议入口、是否流式、结束信号、最终解析 token 数，以及 `usage_shape`。桌面调用关联 ID 仅在通过现有 UUID 校验后记录。

`usage_shape` 只保留固定的四个路径（`usage`、`response.usage`、`data.usage`、`data.response.usage`）、固定 token 字段的非负整数、字段类型异常标记、帧数/字节数，以及枚举化结束原因/状态。`saw_nonzero_usage` 和 `zero_after_nonzero` 可以区分从未收到用量与收到过正数后被空/零帧覆盖的情况。观察器在每次上游尝试开始时重置。

不记录提示词、回答、原始响应、任意 JSON 字段、凭据、请求/响应头集合或带参数 URL。未知状态只记录 `other`，非安全模型标识和上游请求 ID 会留空。计数为字符串、负数或溢出时只标记该固定字段的类型异常，绝不保存原值。

日志沿用现有全局每分钟最多一条的采样规则，`missing_usage_total` 是累计异常数，`suppressed_since_last` 是本次日志前被抑制的异常数。因此这不是每次异常的完整响应留档，不能据此重建已遗失的历史原始响应。日志继续进入既有服务日志和 Ops 系统日志管理流程，不新增接收端或外发路径。
